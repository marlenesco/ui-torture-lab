# Security Policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use
[GitHub Private Vulnerability Reporting](https://github.com/marlenesco/ui-torture-lab/security/advisories/new).

Relevant reports include unintended page access, permission abuse, redaction
bypass, Current Run Result exposure, code injection, unexpected network
requests, extension-context messaging flaws, privilege escalation, unsafe
Restore, or supply-chain compromise.

Include the smallest safe reproduction possible. Do not send real credentials,
tokens, authenticated URLs, private page content, proprietary applications,
personal data, or complete unredacted reports.

## Support policy

Security handling is best-effort. The project does not promise an
acknowledgement or resolution time, embargo agreement, bug bounty, incident
response service, or support for modified distributions. Maintainers may ask
for a synthetic fixture or other redacted evidence before evaluating a report.

Only unmodified releases published through official UI Torture Lab channels are
covered by the project's Public Product Contract.
