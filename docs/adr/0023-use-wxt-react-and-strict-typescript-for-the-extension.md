# Use WXT, React, and strict TypeScript for the extension

The Chrome MV3 application uses WXT for extension build and entrypoints, React only for rendering and coordinating extension UI, and one strict TypeScript baseline across extension and Engine. The Engine owns the Run state machine, domain transitions, page side effects, redaction, and reporting; React consumes immutable snapshots, issues explicit commands, and keeps only presentation state. One Document Runtime owns Active Run State independently of its detachable UI: collapse, unmount, Side Panel closure, Shadow host loss, or React failure never terminates a Run or triggers implicit Restore, and reopening the UI reconnects to the existing Engine without reacquiring Baseline or reapplying Mutations. Explicit developer commands and Engine-controlled safety aborts may initiate Restore, while document and tab termination end the runtime. WXT, React, Chrome APIs, routers, and general state-management frameworks never enter the Engine, while dependency versions and upgrades remain intentional. The stack is accepted only after the UI technical spike validates Shadow host isolation, event behavior, measurement integrity, lifecycle, idempotent UI remount, reinjection, and bundle cost.
