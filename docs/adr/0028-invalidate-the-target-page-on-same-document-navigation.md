# Invalidate the Target Page on same-document navigation

Any reliably observed top-level same-document navigation invalidates the Explicit Page Grant even when Chrome preserves the same Document. Stable-route SPAs remain supported, but an observed history, fragment, or router transition never carries an Active Run into the resulting logical Target Page. If a Run is active, the Engine stops new Mutation and measurement work, performs a safety abort, attempts conflict-aware best-effort Restore, finalizes only already-supported Evidence, and retains the result as a non-live Previous-Target Snapshot; a Restore conflict requires a true reload before another Run. The extension neither intercepts navigation nor automatically acquires a new Baseline, and the new route requires another toolbar action. Detection uses only standard Web APIs proven reliable from the `ISOLATED` world, without `webNavigation`, `tabs`, `MAIN`-world code, History API patching, or a page bridge. If the technical spike cannot demonstrate reliable observation, the Public Product Contract instead requires Restore before SPA route changes and explicitly treats route transitions during an Active Run as unsupported.
