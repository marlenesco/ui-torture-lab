# Run Target Page code only in the ISOLATED world

All UI Torture Lab code injected into or operating directly against the Target Page executes inside Chrome's `ISOLATED` world, and the MVP injects no executable code, helper, or communication bridge into the page's `MAIN` world. The supported geometric Scenarios and Detectors use only the shared DOM, CSSOM, standard Web Platform observation APIs, and browser rendering state; they do not inspect application globals, framework internals, routers, stores, or runtime functions. Extension contexts communicate through narrow, typed Chrome runtime messages rather than `window.postMessage`, custom events, DOM attributes, or inserted script elements. This boundary prevents the page from directly addressing Engine state and reduces interference, security exposure, CSP coupling, and application-specific dependencies, but it does not isolate the shared DOM: the page can still change, replace, or disconnect nodes and can interfere with extension-owned hosts. Strict node identity, bounded stability, exact write verification, inconclusive comparisons, and conflict-aware Restore therefore remain necessary. Any future capability requiring `MAIN`-world execution is unsupported until it receives a separate threat model, validation matrix, Public Product Contract update, and architectural decision.
